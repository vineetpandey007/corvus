# API Reference

Base URL (local dev): `http://localhost:8000`
Interactive docs (auto-generated by FastAPI): `http://localhost:8000/docs`

All routes except `/`, `/health`, `/auth/register`, and `/auth/login`
require authentication: either an `Authorization: Bearer <token>` header
(from login/register) or an `X-API-Key: <key>` header matching
`API_SERVICE_KEY` in `.env`.

---

## Auth

### `POST /auth/register`
Rate-limited to 5/minute per IP. Email is required and must be unique.

**Request**
```json
{ "username": "analyst01", "email": "analyst01@example.com", "password": "ChangeThisPassword123!" }
```

**Response** `201 Created`
```json
{ "access_token": "eyJhbGciOi...", "token_type": "bearer" }
```

Always creates an `analyst`-role account. Use `scripts/create_admin.py`
for an admin account.

### `POST /auth/login`
Rate-limited to 10/minute per IP. `identifier` accepts either the
username or the email.

**Request**
```json
{ "identifier": "analyst01", "password": "ChangeThisPassword123!" }
```

**Response** `200 OK` — same shape as register. `401` on bad credentials.

### `POST /auth/forgot-password`
Rate-limited to 5/minute per IP. Always returns the same generic message
whether or not the account exists (prevents user enumeration). Sends a
reset link via `src/utils/email_service.py` — dev mode (default) logs it
to the console and `<app-data-dir>/dev_email_outbox.jsonl` instead of
actually emailing it; see `docs/SETUP.md` to switch to real SMTP.

**Request**
```json
{ "identifier": "analyst01@example.com" }
```

**Response** `200 OK`
```json
{ "message": "If an account with that username or email exists, a password reset link has been sent." }
```

### `POST /auth/reset-password`
Rate-limited to 10/minute per IP. `token` comes from the link in the
reset email; single-use, expires after 30 minutes.

**Request**
```json
{ "token": "<from the reset link>", "new_password": "NewPassword123!" }
```

**Response** `200 OK` on success. `400` if the token is invalid, expired, or already used.

### `POST /auth/otp/request`
Rate-limited to 5/minute per IP. Same generic-response pattern as
forgot-password. Sends a 6-digit code (dev mode: logged/outboxed), valid
for 10 minutes, capped at 5 verification attempts.

**Request**
```json
{ "identifier": "analyst01" }
```

### `POST /auth/otp/verify`
Rate-limited to 10/minute per IP. Issues the same JWT shape as `/auth/login` on success.

**Request**
```json
{ "identifier": "analyst01", "code": "123456" }
```

**Response** `200 OK` — `{ "access_token": "...", "token_type": "bearer" }`. `400` on wrong/expired/used code, `429` after 5 failed attempts against the same code.

## Cases (persistent, access-controlled, encrypted at rest)

### `POST /cases`
Create a new case, owned by the authenticated analyst.

**Request**
```json
{ "title": "Operation Nightfall", "legal_basis": "Warrant #2026-XXXX" }
```

**Response** `201 Created`
```json
{ "case_id": "10248af7", "title": "Operation Nightfall", "legal_basis": "Warrant #2026-XXXX" }
```

### `GET /cases`
List the authenticated analyst's own cases.

### `POST /cases/{case_id}/ingest`
Add posts to a case. Text is encrypted before storage; the correlation
pipeline (stylometry, PGP, wallet, username) runs immediately and updates
the case's identity graph.

**Request**
```json
{
  "posts": [
    { "alias": "shadowbroker99", "text": "...", "source": "forum_alpha" },
    { "alias": "night_wolf_23", "text": "...", "source": "forum_beta" }
  ]
}
```

**Response** `200 OK`
```json
{
  "case_id": "10248af7",
  "ingested": 2,
  "graph": { "nodes": [...], "edges": [...] }
}
```

### `GET /cases/{case_id}/graph`
Return the current identity graph for a case.

### `GET /cases/{case_id}/posts`
Return the case's stored posts, decrypted for analyst review.

All `/cases/{case_id}/*` routes return `404` if the case doesn't exist
**or** belongs to a different analyst — ownership is not distinguishable
from non-existence in the response, by design.

## OAuth Login (Google / GitHub)

### `GET /auth/oauth/{provider}/login`
`provider` is `google` or `github`. Redirects the browser to the
provider's consent screen. Returns `501` with a clear message if that
provider's credentials aren't set in `.env` (see `docs/SETUP.md`).

### `GET /auth/oauth/{provider}/callback`
The provider redirects back here after consent. Exchanges the code,
fetches the profile, finds-or-creates (or links, by matching email) a
local account, and redirects to
`{frontend}/#/oauth-callback?token=<jwt>`. Not meant to be called
directly — this is a provider redirect target, not a frontend-callable
endpoint. On any failure, redirects to `{frontend}/#/login?oauth_error=...`
instead of returning a raw error page.

## NLP Queries & Suggestions

Rule-based (no LLM/API key) — every answer and suggestion is derived
directly from the case's own graph/report data. See `src/nlp/`.

### `POST /cases/{case_id}/query`
**Request:** `{ "query": "Summarize this case" }`
**Response:** `{ "answer": "...", "matched_intent": "summary", "follow_up_questions": ["...", "..."] }`
Supported question types: summary/counts, strongest/weakest finding,
a named alias's connections, filtering by correlation type (stylometry/
PGP/wallet/username), and uncorrelated aliases. Unrecognized phrasing
returns a help message listing example queries rather than guessing.

### `GET /cases/{case_id}/suggestions`
**Response:** `{ "case_id": "...", "suggestions": [{ "suggestion": "...", "reason": "..." }, ...] }`
Investigative next-step heuristics (e.g., flagging isolated aliases,
single-signal-only pairs needing corroboration, high-confidence leads to
prioritize) — see `src/nlp/suggestions.py` for the exact trigger rules.

## Reports & Export

### `GET /cases/{case_id}/report`
Structured bullet-point report: summary stats, findings sorted by
confidence (highest first), and uncorrelated aliases. Every line is
derived directly from the graph's own data — see
`src/reporting/report_generator.py`.

### `GET /cases/{case_id}/export/txt`
Plain-text bullet-point version of the report, as a file download
(`Content-Disposition: attachment`).

### `GET /cases/{case_id}/export/pdf`
Formatted PDF version of the report (via `reportlab`), as a file download.

PNG/JPG graph image export is **client-side** (Cytoscape.js's own
`cy.png()`/`cy.jpg()` in `frontend/src/components/GraphView.jsx`) rather
than an API endpoint — it exports exactly what's currently on screen
(the analyst's current pan/zoom), not a fresh server-side render.

## Standalone Analysis Tools

Quick one-off checks that don't require opening a case. All require auth.

### `POST /analyze/text`
```json
{ "alias_a": "shadowbroker99", "text_a": "...", "alias_b": "night_wolf_23", "text_b": "..." }
```
```json
{ "alias_a": "...", "alias_b": "...", "similarity_score": 0.83, "likely_same_author": true, "threshold_used": 0.75 }
```

### `POST /correlate/pgp`
Same request shape as above (text_a/text_b containing PGP key blocks).
```json
{ "match": true, "fingerprint": "ABCD 1234 ...", "confidence": 0.98 }
```

### `POST /correlate/username`
```json
{ "alias_a": "shadowbroker99", "alias_b": "shadow_broker_99" }
```
```json
{ "levenshtein_score": 0.89, "phonetic_match": true, "confidence": 0.55, "likely_related": true }
```

### `POST /trace/wallet`
```json
{ "address": "0xABCDEF...", "chain": "ethereum" }
```
`chain` is `"ethereum"` or `"bitcoin"`. Always returns `200` — a failed
trace (rate-limited/unreachable explorer) comes back as
`{"error": true, "notes": "...", "linked_addresses": [], ...}` rather than
a 5xx, since third-party API flakiness is expected, not a server fault.

### `GET /graph/{case_id}`
Quick-lookup graph retrieval by case_id string alone (no DB ownership
check — shares the same in-process graph backend as the `/cases` routes).
Prefer `/cases/{case_id}/graph` for access-controlled retrieval.

---

## `GET /health`
Liveness check, `{"status": "ok"}`. Rate-limited per `config.yaml ->
security.rate_limit_per_minute` (default 60/minute).
